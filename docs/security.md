# Модель безопасности и исходящих данных

English version: [security.en.md](security.en.md).

## Каналы исходящих данных

1. LLM endpoint получает активный контекст. Контекст выбирает локальный ContextManager.
2. HTTP и web search работают только после подтверждения и только для хостов из allowlist.
3. Именованные подключения к БД и SSH работают только после подтверждения. Секреты остаются
   в конфигурации.
4. Endpoint эмбеддингов существует, только если база знаний и URL эмбеддингов включены явно.
5. Проверка подключения к провайдеру (`/api/settings/models/providers/{id}/test`) отправляет
   запрос `GET /models`. Запрос не содержит данных диалога.

Каждая попытка записывается в `outbound_audit`. Журнал хранит метаданные и хеш. Журнал не
хранит само содержимое. Так можно подтвердить факт и объём отправки без второй копии
конфиденциальных данных.

Перед записью в журнал, в `Session.error` и в события сервер удаляет из текста ошибки
провайдера ключ API и типовые формы ключей.

В распределённом режиме Redis Stream содержит только ID сессии. Pub/Sub передаёт события
интерфейса со служебными ID и статусами. Тексты диалогов остаются в PostgreSQL. Worker
загружает их по ID сессии. Не открывайте Redis и PostgreSQL во внешнюю сеть. Compose не
публикует их порты на хосте.

## Доступ к интерфейсу и API

- Сервер проверяет точный заголовок `Host`. Это защищает от DNS rebinding.
- Браузер входит по одноразовой ссылке. После входа сессию держит cookie `HttpOnly;
  SameSite=Strict`. При HTTPS cookie имеет префикс `__Host-` и флаг `Secure`.
- Изменяющие запросы требуют разрешённый `Origin` и CSRF-токен.
- WebSocket проверяет `Origin` и cookie до принятия соединения и повторно каждые 5 секунд.
- `X-Agent-Token` нужен только для CLI, скриптов и healthcheck.

Подробности: [ADR 0003](adr/0003-browser-authentication.md).

## Локальные границы

`SafeProjectFS` выполняет запись, правку и удаление файлов через файловые дескрипторы. Он не
следует за symlink ни в одном компоненте пути. Временный файл создаётся в той же папке. Замена
файла атомарная. `PathGuard` запрещает `..`, выход за абсолютный путь проекта и выход через
symlink при чтении.

Shell получает `cwd` корня проекта, ограниченный timeout и ограниченный вывод. Shell всегда
требует подтверждения. Команда работает в своей группе процессов. Stop, timeout и переполнение
вывода завершают всю группу. Запуск backend под отдельным непривилегированным пользователем
остаётся рекомендуемой второй границей защиты.

Файловые инструменты блокируют `.env`, `.npmrc`, закрытые ключи и типовые файлы с учётными
данными. Shell не наследует `AGENT_*`, облачные учётные данные и окружение SSH agent. Вывод
stdout и stderr ограничен по памяти. Одобренный shell всё равно может читать файлы, доступные
системному пользователю, и открывать сетевые соединения. Поэтому non-root пользователь в
контейнере, read-only rootfs и внимательная проверка подтверждений обязательны.

## Ключи моделей

`config/models.yaml` не содержит ключей. Провайдер ссылается на переменную окружения через
`api_key_env`. Ключ, введённый в интерфейсе, сервер шифрует через Fernet. Мастер-ключ —
`AGENT_SECRET_KEY`. API никогда не возвращает ключ: только признак `api_key_set` и последние
четыре символа. Подробности: [ADR 0004](adr/0004-model-configuration-layers.md).

## Что не является гарантией

Подтверждение показывает намерение пользователя. Оно не доказывает безопасность команды или
SQL. Перед подтверждением интерфейс показывает имя инструмента, уровень риска и аргументы.
Для доступа из внешней сети нужен TLS reverse proxy. Вход по ссылке не заменяет TLS, сетевой
firewall и ротацию секретов.
