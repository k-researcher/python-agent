# Модель безопасности и исходящих данных

## Каналы исходящих данных

1. LLM endpoint — получает выбранный локальным ContextManager активный контекст.
2. HTTP/web search — только после Approval и только для DNS/host allowlist.
3. Именованные DB и SSH — только после Approval; секреты остаются в конфигурации.
4. Embedding endpoint — существует только при явном включении KB и URL embeddings.

Каждая попытка фиксируется в `outbound_audit`. Журнал хранит метаданные и хеш, а не
payload. Это позволяет подтвердить факт и объём отправки без создания второй копии
чувствительного содержимого.

В distributed-режиме Redis Stream содержит только `session_id`, а Pub/Sub — UI-события
со служебными идентификаторами и статусами. Тексты диалогов остаются в PostgreSQL и
загружаются worker непосредственно по session ID. Не следует публиковать Redis или
PostgreSQL наружу; Compose не открывает их порты на host.

## Локальные границы

`PathGuard` запрещает `..`, абсолютные выходы и symlink escape. Shell получает
`cwd` корня проекта и ограниченный timeout/output, но остаётся мощным инструментом и
всегда требует Approval. Запуск backend под отдельным непривилегированным системным
пользователем остаётся рекомендуемой второй границей защиты.

Автоматические файловые инструменты блокируют `.env`, `.npmrc`, private key и типовые
credential-файлы. Shell не наследует `AGENT_*`, cloud credentials или SSH agent
окружение; его stdout/stderr ограничены по памяти. При этом одобренный shell остаётся
способен читать доступные системному пользователю файлы и открывать сеть, поэтому
контейнерный non-root user, read-only rootfs и внимательная проверка Approval являются
обязательными границами.

LLM-профили хранят API keys только в конфигурации процессов. В сессии находится имя
профиля, а в public config и audit — имя модели и hostname без ключа.

## Не является гарантией

Approval подтверждает намерение пользователя, но не доказывает безопасность команды
или SQL. Перед разрешением UI показывает имя инструмента, risk level и аргументы.
Для публикации в сеть необходим TLS reverse proxy; встроенный API token не заменяет
TLS, сетевой firewall и ротацию секретов.
