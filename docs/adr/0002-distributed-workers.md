# ADR 0002: Redis Streams и отдельные workers

English version: [0002-distributed-workers.en.md](0002-distributed-workers.en.md).

## Статус

Принято. Режим необязательный. Embedded runtime остаётся режимом по умолчанию.

## Контекст

Один процесс не может обслуживать много параллельных сессий. Несколько процессов должны
использовать общее состояние сессий. Два процесса не должны выполнять одну сессию
одновременно.

## Решение

В распределённой конфигурации:

- PostgreSQL хранит состояние сессий.
- Redis Stream — долговечная очередь сигналов о сессиях, готовых к выполнению.
- Redis Pub/Sub передаёт временные события интерфейса.
- API не выполняет цикл агента и вызовы инструментов.
- Workers используют одну consumer group и распределённую блокировку для каждого ID сессии.

## Надёжность

Worker подтверждает задание в stream после возврата цикла агента. Если worker не подтвердил
задание, другой worker может забрать его после visibility timeout. Runtime сохраняет
состояния ответа ассистента и вызовов инструментов перед каждым внешним действием. Поэтому
worker может продолжить цикл после сбоя процесса.

После сбоя вызов инструмента со статусом `running` имеет неизвестный результат. Runtime
записывает для него результат с ошибкой и не выполняет вызов повторно. Автоматический повтор
может повторить платёж, SQL update, SSH-команду или запись файла. Поэтому runtime запрашивает
у пользователя новое явное действие.

## Последствия

- Redis Pub/Sub — не журнал. Источник истории событий — таблица `events`. WebSocket только
  сообщает интерфейсу, что нужно снова прочитать состояние.
- Остановка выполняющейся сетевой операции кооперативная. Её timeout задаёт верхний предел.
- Многопроцессный режим не разрешает SQLite.
- Выполнение внешнего побочного эффекта ровно один раз невозможно, если целевая система не
  принимает idempotency key.
