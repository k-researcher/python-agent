# ADR 0001: самостоятельный Python runtime

## Решение

Использовать FastAPI, asyncio и SQLite в одном локальном процессе. HTTP и WebSocket
работают на одном порту. Состояние сессий хранится в БД, а не в памяти или JSON-файлах.

## Причины

- единая кроссплатформенная команда запуска;
- атомарные изменения состояния;
- восстановление после перезапуска;
- отсутствие самописной реализации WebSocket;
- явный централизованный контроль подтверждений.

## Развитие решения

Runtime поддерживает ограниченный локальный контекст, дочерние сессии, capability
flags, approvals и audit исходящих каналов. SQLite остаётся вариантом по умолчанию;
для состояния runtime разрешён PostgreSQL через async driver.

## Последующее решение

Однопроцессный режим сохранён для локальной работы. Горизонтальное масштабирование
описано в ADR 0002 и использует PostgreSQL, Redis Streams, Pub/Sub и отдельные workers.
