# ADR 0003: Вход в браузере по одноразовой ссылке

English version: [0003-browser-authentication.en.md](0003-browser-authentication.en.md).

## Статус

Принято. Заменяет ручной ввод API-токена в интерфейсе.

## Контекст

Прежний интерфейс просил пользователя ввести API-токен в форму. Токен хранился в памяти
JavaScript и терялся после каждой перезагрузки страницы. Без токена локальный API принимал
все запросы. Вредоносная веб-страница могла через DNS rebinding отправлять запросы в
локальный API и подтверждать shell-команды. Удалённый доступ обязателен.

## Решение

1. Сервер проверяет точный заголовок `Host` каждого запроса. Разрешённые имена задаёт
   `AGENT_ALLOWED_HOSTS`. Шаблоны со звёздочкой запрещены.
2. Браузер входит по одноразовой ссылке. При запуске, если активной сессии нет, сервер
   выводит ссылку в консоль. На localhost сервер также открывает ссылку в браузере.
   Команда `agent auth link` создаёт новую ссылку.
3. Код входа находится во fragment URL (`#login=...`). Поэтому прокси и журналы доступа его
   не получают. Интерфейс удаляет fragment и отправляет код POST-запросом.
4. Сервер создаёт сессию и устанавливает cookie `HttpOnly; SameSite=Strict; Path=/`. При
   HTTPS имя cookie имеет префикс `__Host-` и флаг `Secure`.
5. База данных хранит только SHA-256-хеши кодов входа и ID сессий. Код входа одноразовый.
   Сессия имеет абсолютный срок действия. Сессию можно отозвать.
6. Каждый изменяющий запрос должен иметь разрешённый заголовок `Origin` и CSRF-токен сессии
   в `X-Agent-CSRF`.
7. Handshake WebSocket должен иметь разрешённый `Origin` и действительную cookie сессии.
   Сервер проверяет их до принятия соединения. Сервер повторно проверяет сессию каждые
   5 секунд.
8. `X-Agent-Token` остаётся для CLI, скриптов и healthcheck. Действительный токен не
   разрешает чужой `Origin`.
9. Для удалённого доступа `AGENT_PUBLIC_ORIGIN` должен использовать `https://`. Заголовки
   `X-Forwarded-*` может устанавливать только reverse proxy из `AGENT_TRUSTED_PROXY_IPS`.

## Последствия

- Интерфейс не показывает и не хранит секрет. JavaScript не может прочитать cookie сессии.
- Все экземпляры API используют общее состояние входа через базу данных. Это необходимо для
  распределённого режима.
- После изменения публичного origin пользователи должны войти снова.
- `/api/health` публичный и возвращает только статус сервиса. Сведения об инфраструктуре
  находятся в `/api/ready`. Этот endpoint требует аутентификации.
