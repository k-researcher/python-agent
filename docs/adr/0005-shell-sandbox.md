# ADR 0005: Песочница ОС для shell-команд

English version: [0005-shell-sandbox.en.md](0005-shell-sandbox.en.md).

## Статус

Принято. Режим по умолчанию — `off`. Для воркеров агента режим `required` обязателен.

## Контекст

Агент пишет код и запускает его через shell: тесты, скрипты, миграции. Список разрешённых
команд не защищает. Например, `pytest` выполняет тесты, которые написал сам агент. Такой тест
может прочитать `~/.ssh`, `.env` другого проекта или настройки пользователя и вернуть их в
выводе команды. Требование: код агента может делать всё, но только внутри текущего проекта.

## Решение

1. Shell-команда запускается через `sandbox-exec` (macOS) с профилем «запрещено всё, кроме
   явно разрешённого». Код: `src/agent/sandbox.py`.
2. Чтение и запись разрешены для папки проекта и временной папки сессии.
3. Только чтение разрешено для узкого списка системных путей, интерпретатора процесса агента
   и активной папки инструментов разработчика. Пути `/usr/local` и `/System/Volumes/*` закрыты.
4. Сеть закрыта. Сведения о других процессах, общая память и семафоры POSIX закрыты.
   `sysctl` открыт только по списку имён. Stdin команды закрыт.
5. Список разрешённых путей задают только процесс агента и доверенная настройка
   `AGENT_SHELL_SANDBOX_READ_PATHS`. Файлы проекта на профиль не влияют, потому что код
   агента может их изменить.
6. Временная папка сессии находится вне проекта. Перед каждой командой сервер проверяет её:
   настоящая папка, не ссылка, владелец — текущий пользователь, права `0700`. При отклонении
   команда не запускается.
7. `HOME`, `TMPDIR` и `XDG_*` указывают на временную папку сессии. Git не читает системную
   конфигурацию (`GIT_CONFIG_NOSYSTEM`, `GIT_ATTR_NOSYSTEM`).
8. Режимы настройки `AGENT_SHELL_SANDBOX`:
   - `off` — песочницы нет;
   - `auto` — песочница работает, если система её поддерживает;
   - `required` — без работающей песочницы команда не запускается.
9. `available()` проверяет песочницу пробным запуском. Вложенный запуск внутри песочницы
   невозможен, поэтому проверка там возвращает `False`.

## Последствия

- Тесты, линтеры, типизация, миграции и `git` работают внутри проекта без изменений.
- Команды, которым нужна сеть (установка пакетов, `git push`), в песочнице не работают.
  Для них нужен отдельный подтверждённый шаг вне песочницы или `AGENT_SHELL_SANDBOX_NETWORK`.
- Программа вне доверенных путей не запускается. Это относится и к виртуальному окружению
  самого агента.
- Для git worktree нужна настройка чтения папки `.git` основного репозитория.
- Песочница есть только для macOS. В Linux её роль выполняет контейнер или отдельный
  пользователь ОС; бэкенд для Linux — отдельная задача.

## Остаточные риски

- Hard link на внешний файл, который пользователь сам создал в проекте, читается. Изнутри
  песочницы такую ссылку создать нельзя.
- Список верхних папок корня `/` виден: его требует загрузчик программ macOS.
- Песочница не ограничивает процессор, память и число процессов.
- Потомок, который вызвал `setsid()`, может пережить остановку группы процессов.
