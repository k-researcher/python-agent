# Подключение GigaChat от Сбера

Пошаговая инструкция для python-agent. Общие настройки описаны в [README](../README.md).

Есть два способа:

| Способ | Где работает | Кто видит ваши запросы |
|---|---|---|
| Облачный GigaChat API | Windows 10, macOS | Сбер |
| Локальная модель GigaChat 3.1 Lightning | macOS | никто: запросы не покидают компьютер |

Инструкция для Windows 10 описывает облачный способ.
Для macOS описаны оба способа.

## Что нужно знать до начала

**Сбер видит всё, что вы отправляете в облачный GigaChat.**
Сбер — российский оператор данных и обязан передавать данные по запросу
в установленном законом порядке. Не отправляйте в облачный GigaChat то,
что не должен видеть Сбер. Для приватной работы используйте локальную модель.

**Серверы Сбера используют сертификат Минцифры.**
Это «Russian Trusted Root CA». Windows, macOS и Python ему не доверяют,
поэтому без него соединение со Сбером не открывается.

Агент доверяет этому сертификату ограниченно:

- Сертификат читается из файла в папке проекта. В Windows, macOS и браузер
  он не устанавливается.
- Сертификату доверяют только соединения агента с GigaChat:
  получение токена, запросы к модели и кнопка проверки соединения.
- Соединения с GigaChat доверяют только этому сертификату. Обычные
  мировые центры сертификации для них не действуют.
- Остальные соединения агента, системы и браузера этот сертификат
  не принимают. Подделать с его помощью сертификат другого сайта
  для этих соединений нельзя.
- Переменные окружения `SSL_CERT_FILE` и `SSL_CERT_DIR` не меняют доверие
  соединений агента с моделями. Некоторые инструкции в интернете советуют
  прописать в них сертификат Минцифры. Для агента этого делать не нужно,
  и на агент это не повлияет.
  Исключение: прокси с адресом `https://...` в `HTTPS_PROXY` или `ALL_PROXY`.
  Соединение агента с таким прокси эти переменные учитывает. Соединение
  с самой моделью внутри прокси по-прежнему проверяется правилами выше.
  Не прописывайте сертификат Минцифры в `SSL_CERT_FILE` и `SSL_CERT_DIR`.

Тесты в `tests/unit/test_provider_tls_isolation.py` проверяют эти правила
на настоящем TLS-соединении. Тесты используют клиенты агента: запросы
к модели, получение токена, проверку соединения и эмбеддинги.
Тест подменяет `SSL_CERT_FILE` и проверяет, что подмена не действует.

Чего эта защита не делает:

- Провайдер интернета видит, к каким серверам вы подключаетесь и когда.
  Содержимое HTTPS он не видит. Это не зависит от сертификата.
- Если сертификат Минцифры уже установлен в систему, ему доверяют все
  программы, которые используют системное хранилище. Агент на это не влияет.
  Как проверить — в шаге 3.
- Кто может менять файлы проекта или базу агента, тот может изменить
  и настройку сертификата. Храните проект в папке, доступной только вам.

## Windows 10: облачный GigaChat

Пример ниже считает, что проект лежит в `D:\python-agent`.
Если папка другая, подставьте свой путь.
Все команды выполняйте в «Командной строке» (`cmd`).

### Шаг 1. Получите ключ авторизации

1. Откройте <https://developers.sber.ru/studio> и войдите через Сбер ID.
2. Создайте проект **GigaChat API**.
3. Откройте настройки API проекта.
4. Получите **ключ авторизации** (Authorization key) и скопируйте его.
5. Запомните, какой у вас scope: для физических лиц это `GIGACHAT_API_PERS`.

Нужен именно ключ авторизации, а не временный токен доступа.
Токен действует 30 минут, агент получает его сам.

Ключ показывают один раз. Если вы его потеряли, создайте новый.
Никому не показывайте ключ: не отправляйте его в чат, не вставляйте в YAML
и не коммитьте в git.

### Шаг 2. Обновите проект

1. Остановите агент: в окне, где он работает, нажмите `Ctrl+C`.
2. Перейдите в папку проекта и получите изменения:

```bat
D:
cd \python-agent
git pull
uv sync --extra dev
```

3. Проверьте, что файл сертификата не изменён:

```bat
certutil -hashfile config\certs\russian_trusted_ca.pem SHA256
```

Хеш должен совпасть:

```text
be9dcd199576967219f0ff18abe7f513a7f9e02b595b42c8bdaedb3306bf6187
```

Если хеш другой, не продолжайте. Выполните
`git checkout -- config\certs\russian_trusted_ca.pem` и проверьте ещё раз.

### Шаг 3. Проверьте, нет ли сертификата Минцифры в Windows

```bat
certutil -store Root | findstr /i "Russian Trusted"
certutil -user -store Root | findstr /i "Russian Trusted"
```

- Команды ничего не вывели — сертификата в системе нет. Это хорошо.
- Команда вывела строку с `Russian Trusted` — сертификат установлен в Windows.
  Его могли установить «Госуслуги», программа банка или ИТ-отдел.
  Ему доверяют все программы Windows, а не только агент.

Если сертификат установлен и вы этого не хотите, удалите его:
`Win+R` → `certmgr.msc` → «Доверенные корневые центры сертификации» →
«Сертификаты» → «Russian Trusted Root CA» → «Удалить».
Перед удалением учтите: некоторые российские сайты и программы перестанут
открываться. На рабочем компьютере сначала спросите ИТ-отдел.

### Шаг 4. Решите, где хранить ключ

Ключ можно ввести в интерфейсе или записать в файл `.env`.
Выберите один способ.

| Способ | Как хранится ключ | Когда выбирать |
|---|---|---|
| Интерфейс | В базе агента в зашифрованном виде | Удобнее, ключ не лежит в открытом файле |
| Файл `.env` | Открытым текстом в файле | Если вы настраиваете агент без браузера |

**Если вы выбрали интерфейс**, сейчас ничего не делайте.
Ключ вы введёте в шаге 8 после запуска агента.

Ключ в интерфейсе зашифрован ключом из файла `data\secret.key`.
Не удаляйте этот файл: без него сохранённые ключи нельзя прочитать.

**Если вы выбрали файл `.env`:**

1. Откройте файл `D:\python-agent\.env` в Блокноте.
2. Добавьте в конец строку. Вместо `ваш_ключ` вставьте ключ из шага 1:

```dotenv
GIGACHAT_AUTH_KEY=ваш_ключ
```

3. Сохраните файл. Остальные строки не меняйте.

В обоих способах пишите ключ без кавычек и без слова `Basic`:
агент добавляет его сам.

### Шаг 5. Добавьте GigaChat в `config/models.yaml`

1. Откройте `D:\python-agent\config\models.yaml` в Блокноте.
2. В раздел `providers:` добавьте блок `sber`:

```yaml
providers:
  sber:
    kind: openai
    base_url: https://gigachat.devices.sberbank.ru/api/v1
    dialect: functions
    ca_bundle: config/certs/russian_trusted_ca.pem
    auth:
      type: oauth_client_credentials
      token_url: https://ngw.devices.sberbank.ru:9443/api/v2/oauth
      key_env: GIGACHAT_AUTH_KEY
      scope: GIGACHAT_API_PERS
```

3. В раздел `models:` добавьте блок `sber`:

```yaml
models:
  sber:
    provider: sber
    model: GigaChat-2-Max
    context_window: 32768
    max_tokens: 4096
    reasoning: {supported: false}
```

4. Сохраните файл.

Правила для этого файла:

- Не создавайте второй раздел `providers:` или `models:`.
  Добавьте блоки в существующие разделы.
- Делайте отступы пробелами. Табуляция ломает YAML.
- Строку `ca_bundle` не удаляйте. Без неё соединение со Сбером не откроется.
- Указывайте `ca_bundle` только у провайдера `sber`.
- Путь `config/certs/...` отсчитывается от папки проекта.

Пояснения к значениям:

- `base_url` — адрес для запросов. Новый адрес Сбера `https://api.giga.chat/v1`
  из нашей сети отвечал нестабильно. Поэтому в примере старый адрес:
  он работал стабильно. Если старый адрес перестанет работать, укажите новый.
- `scope` — для физических лиц `GIGACHAT_API_PERS`. Для ИП и юрлиц укажите
  scope своего договора: `GIGACHAT_API_B2B` или `GIGACHAT_API_CORP`.
- `model` — имя модели в API Сбера. Физическим лицам в бесплатном режиме
  доступна также `GigaChat-3-Ultra`.
- `context_window` — лимит контекста для агента. 32768 — осторожное значение.
  Точный лимит модели смотрите на странице моделей Сбера.

### Шаг 6. Удалите сервер GigaChat, созданный через форму

Форма «Подключить сервер» пока не умеет настраивать GigaChat: в ней нет полей
для ключа авторизации Сбера и для сертификата. Если вы уже создали подключение
через форму, удалите его:

1. Откройте в интерфейсе настройки моделей, раздел «Подключения».
2. Найдите подключение, которое вы создали для GigaChat.
3. Нажмите значок корзины «Удалить» и подтвердите удаление.

Если у подключения `sber` есть кнопка «Сбросить изменения», нажмите её.
Изменения из интерфейса важнее файла и могут перекрыть настройки из шага 5.

### Шаг 7. Проверьте конфигурацию

```bat
uv run pyagent config check --strict
```

Ожидаемый результат начинается с `OK:`. Эта проверка читает файлы,
но не подключается к Сберу.

Если ключ вы введёте в интерфейсе, проверка не видит его и выводит
предупреждение `GIGACHAT_AUTH_KEY ... is not set`. С флагом `--strict`
это ошибка. В этом случае выполните проверку без флага:

```bat
uv run pyagent config check
```

Ожидаемый результат — это предупреждение и строка `OK:`.
Других предупреждений быть не должно.

### Шаг 8. Запустите агент и проверьте

1. Запустите агент:

```bat
uv run pyagent
```

2. Откройте интерфейс в браузере.
3. Если вы выбрали ввод ключа в интерфейсе:
   1. Откройте настройки моделей, раздел «Подключения».
   2. На карточке `sber` нажмите «Ключ».
   3. В поле «Источник ключа» выберите «Сохранить в приложении».
   4. Вставьте ключ из шага 1 в поле «Новый ключ».
   5. Нажмите «Сохранить ключ».
4. Создайте новую сессию и выберите модель `sber`.
5. Напишите «Привет». Ответ должен прийти за несколько секунд.

### Если что-то не работает

| Сообщение | Причина | Что сделать |
|---|---|---|
| `CA bundle file was not found` | Нет файла сертификата | Выполните шаг 2 ещё раз |
| `CA bundle file could not be read` | Файл сертификата испорчен | `git checkout -- config\certs\russian_trusted_ca.pem` |
| `CERTIFICATE_VERIFY_FAILED` | У провайдера нет строки `ca_bundle` или её перекрывает интерфейс | Проверьте шаги 5 и 6 |
| `Token request failed with status 400` или `401` | Неверный ключ или scope | Проверьте ключ в `.env` и `scope` |
| `handshake operation timed out`, нет ответа | Сеть не пропускает соединение | Подождите и повторите, проверьте `base_url` |
| Ошибка 500 при сохранении ключа в форме | Старая версия агента | Выполните шаг 2 |

Подробности ошибки агент пишет в окно, где он запущен.

## macOS, способ А: облачный GigaChat с изоляцией сертификата

Шаги те же, что для Windows. Отличаются только команды.

1. Получите ключ авторизации, как в шаге 1 для Windows.
2. Обновите проект и проверьте хеш файла сертификата:

```bash
cd ~/путь/к/python-agent
git pull
uv sync --extra dev
shasum -a 256 config/certs/russian_trusted_ca.pem
```

Хеш должен совпасть со значением из шага 2 для Windows.

3. Проверьте, что сертификата нет в связке ключей macOS:

```bash
security find-certificate -a -c "Russian Trusted"
security find-certificate -a -c "Russian Trusted" /Library/Keychains/System.keychain
```

Пустой вывод означает, что сертификата в системе нет.

4. Добавьте ключ в `.env`, как в шаге 4.
5. Добавьте блоки в `config/models.yaml`, как в шаге 5.
6. Проверьте конфигурацию и запустите агент:

```bash
uv run pyagent config check --strict
uv run pyagent
```

## macOS, способ Б: полная изоляция на локальной модели

Модель работает на вашем Mac. Запросы не уходят ни в Сбер, ни в интернет.
Сертификат Минцифры и ключ Сбера не нужны.

Модель: **GigaChat 3.1 Lightning** (`ai-sage/GigaChat3.1-10B-A1.8B-GGUF`).
Это официальная сборка Сбера на Hugging Face, лицензия MIT.
В модели 10B параметров, при ответе работают 1,8B.

Чего ждать: модель маленькая. Она хорошо работает с русскими текстами
и короткими задачами. С кодом и длинными цепочками инструментов она
работает заметно хуже облачных моделей.

### Шаг 1. Выберите версию файла

| Файл | Размер | Когда выбирать |
|---|---|---|
| `q8_0` | 11,4 ГБ | Обычная работа. Качество почти как у bf16, остаётся память под длинный контекст |
| `bf16` | 21,4 ГБ | Максимальное качество. Ответ медленнее примерно вдвое, памяти под контекст меньше |

Для Mac с 36 ГБ памяти подходят оба файла. macOS отдаёт модели примерно
три четверти памяти. Остальное нужно системе и программам.

### Шаг 2. Скачайте модель в LM Studio

1. Откройте LM Studio.
2. Откройте поиск моделей.
3. Введите `ai-sage/GigaChat3.1-10B-A1.8B-GGUF`.
4. Проверьте, что автор — `ai-sage`. Сборки других авторов не используйте.
5. Выберите файл `q8_0` или `bf16` и нажмите «Download».

Файлы GGUF содержат только веса модели. При загрузке они не выполняют код.

### Шаг 3. Запустите локальный сервер

1. Откройте вкладку «Developer».
2. Загрузите модель. В настройках загрузки укажите длину контекста 32768.
3. Нажмите «Start Server». Сервер должен работать на `127.0.0.1:1234`.
4. Узнайте точное имя модели:

```bash
curl http://127.0.0.1:1234/v1/models
```

Скопируйте значение поля `id`.

Сервер должен слушать только `127.0.0.1`. Не включайте в LM Studio
доступ из локальной сети: тогда к модели смогут подключиться другие устройства.

### Шаг 4. Добавьте модель в `config/models.yaml`

В раздел `providers:` добавьте блок:

```yaml
  lmstudio:
    kind: openai
    base_url: http://127.0.0.1:1234/v1
    api_key_env: null
```

В раздел `models:` добавьте блок. Вместо `id-модели` вставьте `id` из шага 3:

```yaml
  giga_local:
    provider: lmstudio
    model: id-модели
    context_window: 32768
    max_tokens: 4096
    reasoning: {supported: false}
    pricing: {input_per_mtok: 0, output_per_mtok: 0}
```

- `context_window` должен совпадать с длиной контекста из шага 3.
- `pricing` с нулями нужен, чтобы бюджет сессии не остановил локальную модель.
- Строку `ca_bundle` здесь не добавляйте.

### Шаг 5. Проверьте изоляцию

1. Выполните проверку конфигурации и запустите агент:

```bash
uv run pyagent config check --strict
uv run pyagent
```

2. Создайте новую сессию и выберите модель `giga_local`.
3. Выключите Wi-Fi и отсоедините сетевой кабель.
4. Напишите «Привет».

Если ответ пришёл без сети, модель работает только на вашем Mac.
Включите сеть обратно.

В сессии с `giga_local` агент всё равно может обращаться к сети через
инструменты, например для чтения веб-страниц. Это управляется разрешениями
сессии, а не моделью.

## Сроки действия сертификатов

Файл `config/certs/russian_trusted_ca.pem` содержит три сертификата Минцифры:

| Сертификат | Действует до | SHA-256 |
|---|---|---|
| Russian Trusted Root CA | 27.02.2032 | `D2:6D:2D:02:…:CA:8E:CF:31` |
| Russian Trusted Sub CA (2024) | 19.07.2029 | `21:55:78:50:…:7D:88:A3:F2` |
| Russian Trusted Sub CA (2022) | 06.03.2027 | `BB:BD:E2:10:…:D8:B3:FD:9B` |

Корневой сертификат взят с официального сайта Минцифры (gu-st.ru).
Его отпечаток совпадает с корневым сертификатом в цепочке серверов Сбера.
Оба промежуточных сертификата подписаны этим корневым. Они не расширяют
доверие: всё, что они подписывают, уже проверяется через корневой.

Если Минцифры выпустит новые сертификаты, файл нужно обновить в репозитории.

## Границы проверки

Проверено 12 ноября 2026 года с macOS:

- С файлом сертификата соединение с `ngw.devices.sberbank.ru:9443` открывается.
  Запрос токена с ненастоящим ключом получает от Сбера ответ 400.
- С файлом сертификата `gigachat.devices.sberbank.ru` отвечает 401 без токена.
  Без файла соединение отклоняется с ошибкой проверки сертификата.
- `api.giga.chat` из нашей сети отвечал нестабильно: часть соединений
  обрывалась во время TLS-рукопожатия.
- Соединение с файлом сертификата отклоняет сайт с обычным мировым
  сертификатом (huggingface.co).

Не проверено: ответ модели с настоящим ключом, работа на Windows 10,
ввод ключа через интерфейс в браузере (проверен только тестом серверной части),
работа GigaChat 3.1 Lightning с инструментами агента.
